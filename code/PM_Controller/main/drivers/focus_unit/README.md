U15 使用 UART2：TX GPIO18、RX GPIO17，460800 baud、8N1；采用 ESP-IDF 普通 UART 驱动，不占用 SDM50 的 UART1 / UHCI。初始化失败只记录错误，界面显示 C；UI 任务独占处理和快照读取，无新增任务。

协议见 [FocusUnit UART 协议](../../../../FocusUnit/docs/UART_PROTOCOL.md)。每次只允许一个在途请求；`focus_unit_set_active()` 在活动期间选用 100 ms 查询间隔，空闲选用 1 s，每次查询使用新序号。`focus_unit_request()` 支持 MoveRaw（0x13）、SetCurrentRaw（0x14）、Stop（0x10）和 Glide B 完整寻零（0x11）；忙时不排队，由应用保留待发操作。100 ms 超时最多重发一次完全相同的帧，仍无响应标记通信无效，再定期查询状态；不自动重放结果不确定的运动。校验帧起始、版本、类型、长度、序号、命令和 CRC，坏帧不更新状态。接收缓冲先于超时处理，每轮读取有预算；控制请求直接尝试非阻塞 FIFO 发送，部分发送时记录偏移，发送期限和响应期限均为 100 ms，事务期限不代表线上字节间隔。收到新状态的当轮不再启动下一次查询，先给应用处理状态及发送控制的机会；实际查询间隔受 UI 调度和单在途事务限制。

驱动只负责协议，不读写参数或 UI；上电恢复、运动前 EEPROM 失效和完成保存由 [focus_position](../../app/focus_position/README.md) 负责。ACK 仅表示受理；BUSY / ERROR / 序号冲突等不当作成功，不自动重试新序号。拒绝状态保留至下一次控制获成功 ACK，状态查询不会将拒绝视为成功；通信失败时优先显示 C。状态超过 2.5 s 或事务失败显示通信无效。快照保留完整设备状态，并分别递增成功状态查询序号和已结束控制事务序号；控制最终超时的结果记为 0xff。应用借此区分命令前的旧状态、命令 ACK 及后续运动完成。

2026-11-02：用户日志显示 BLE controller 无可用 CPU0 三级 IRAM 中断。主控启动时将 `focus_unit_init()` 放在一次性的 CPU1 固定任务中，使 UART2 中断由 CPU1 安装；UART 的后续收发 API 仍由 UI 任务调用。该改动旨在减少 CPU0 中断占用，不保证 UART2 原本占用的是三级中断；配网启动前会打印两核中断表核对。未重新编译、烧录或实机验证，串口与编码器闭环行为需复测。
