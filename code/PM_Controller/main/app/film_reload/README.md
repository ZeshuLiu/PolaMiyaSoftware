# FILM_KEY 延时处理

2026-10-20。`film_reload_start()` 在 `ui_start()` 后调用一次，初始化锁存 GPIO，并创建优先级 1、3072 字节栈的低优先级任务。UI 任务优先级仍为 3。

1. 每 1 s 读取一次锁存，GPIO6 高表示有事件；启动时已经存在的事件也会处理，不先清除。
2. 首次检测后记下约 1 s 的处理期限；按秒轮询到期，不重复延长等待。每次循环 `vTaskDelay()` 让出 CPU，等待期间仍可重试相纸保存；多个触发由硬件合并为一个锁存状态。
3. GPIO7 拉高至少 100 ms，再拉低释放，确认 GPIO6 已回低。
4. 清除成功后通过参数服务把 `SETTINGS_FILM_REMAINING` 设为 8，并调用 `settings_commit_film()` 保存到 EEPROM；LVGL 控件仍由 UI 任务在 HOME 可见时更新。
5. 清除失败则记录日志，余量不变；1 s 后重新轮询，如果事件仍存在则再次等待约 1 s 后重试。

从实际事件到清除约为 1–2 s，再加任务调度延迟和 100 ms 脉冲。不使用 GPIO ISR、精密定时器或忙等，不占用 UI 锁。启动失败只记录告警，不中止已有 UI。

本任务不控制吐片电机，不累计快门或电机时长。每秒调用 `settings_commit_film()` 重试保存当前相纸余量；未改变时不写 EEPROM，不把未确认的背光等参数一起保存。写失败只重试保存，不重复复位或扣减，日志只在保存错误状态变化时输出。

UI 在一次吐片完成后结算：首次成功启动至最终停止斜坡目标结束严格超过 5 s，调用 `settings_consume_film()` 扣 1 张并保存，最低 0；5 s 及以内只调用保存接口。中途反向切换不重新计算动作起点，不重复扣减；阈值按目标结束时间计算，不把 UI 调度延迟算入。此累计不是出片传感器反馈。相纸余量开机从 EEPROM 读取；旧记录缺项默认 6。未编译、测试或烧录，实机行为待确认。
