# 对焦位置恢复与掉电保护

手机遥控通过 UI 任务查询 `focus_position_idle()`，在可接收新目标时调用现有 `focus_position_set_target()`。BLE 任务仅收发遥测和命令，运动与 EEPROM 仍由 UI 任务处理。详见 [BLE 遥测和手动对焦](../ble_remote/README.md)。

设置菜单通过 `focus_position_can_home(now_ms)` 和 `focus_position_is_homing()` 获取执行可用性及寻零状态；这两个接口只读 UI 任务状态。实际 `focus_position_home()` 仍自行检查可用性，菜单提示不能替代命令入口检查。此接入不改变运动和 EEPROM 时序。

## 开机恢复

参数服务从 CRC32、长度、范围和提交标记均有效的最新轮换记录加载 RAW / 有效标记。旧记录缺少任一字段时视为无效。先查询并等待 FocusUnit 的 PWM 就绪，确认待初始化、STOP、零占空比后，用 `SetCurrentRaw (0x14)` 设置已存当前位置；主控单独复位、设备仍处于 NORMAL / STOP 且实际 RAW 与保存值一致时也允许恢复。此命令建立位置基准，不驱动电机。收到成功响应后，还须用新的状态查询确认 NORMAL、zero_valid、STOP 和实际 RAW 一致。

无有效位置、状态不符或恢复失败时不自动运动；HOME 显示 `INIT NEEDED`，SETTINGS 可执行 `SEEK ZERO`。通信失败仍显示 C，存储错误显示 E / `SAVE ERROR`。恢复响应不确定时不换新序号自动重放，改为要求寻零。

## 运动与保存顺序

1. 在参数锁内调用 `settings_save_focus(false, 0)`，提交位置失效记录并逐阶段读回验证。失败时不发送运动指令。
2. 使用 `MoveRaw (0x13)` 定位，或 Glide B / seek_zero=1 完整寻零；ACK 只表示受理。连续调整只替换尚未发出的目标，在途帧保持不变。
3. 活动期间用约 100 ms 间隔的新序号查询确认 NORMAL、零位有效、目标一致、REACHED、零占空比，位置误差在 ±50 RAW 内；空闲查询间隔为 1 s。寻零包括触底校验和自动定位到 0 的完整过程。
4. 因设备 REACHED 后仍可能自动纠偏，发送 `Stop (0x10)` 取消纠偏。成功响应后，至少两次新的状态查询确认 STOP、零占空比且实际 RAW 相同。
5. 若已有待发的新目标，则沿用当前已持久化失效的记录，继续定位，不保存马上又要失效的中间位置。没有新目标时只保存此时的**实际 RAW**和有效标记，不保存运动目标。对焦自动保存不会带上尚未确认的背光修改。最终保存成功后结束本次连续调整；保存失败显示错误，保持制动并约每秒重试保存，重试前仍查询停止状态。

后续定位重新执行失效写入。运动中断电留下完整失效记录；完成写入时断电，会加载完整有效记录或回退到此前的失效记录，后者要求初始化。不能只依靠 CRC：旧位置即使 CRC 正确，也不能用于恢复中途断电的运动。

2026-11-02 响应提速：初次调焦在同一轮处理失效写入和命令发送，不再额外等待一个 UI 周期；控制帧立即通过非阻塞 UART FIFO 提交。收到新到位状态后立即发 Stop，取消此前额外一轮查询等待。已建立位置基准的连续调节无需等待上一目标 REACHED，单在途请求结束后即可发送最新目标。新的状态响应优先交给应用，避免查询一直占用发送机会。

最终 EEPROM 写入已完成但读回失败时，参数服务保留“不确定写入”状态；下一次提交即使值相同也重新覆盖并验证目标槽。这样不会把 RAM 中的旧失效值误当作 EEPROM 的确定状态。快门、相纸、手动保存均共用参数锁和同一份已持久化快照。

## 边界

控制响应拒绝、超时、设备故障、堵转或运动期间连续 3 s 无新状态，不保存为有效位置；要求重新寻零，不自动重放不确定的运动。运行中设备复位、意外运动或 STOP 时编码器位置变化，也使位置失效。寻零不是急停，协议 Stop 不能取消寻零；设备本身尚无行程限位及定位超时，本模块不添加新的机械超时假设。

恢复假设断电期间机械位置保持不变。无绝对位置传感器，软件无法判断掉电后的外力移动或编码器未供电时的位置变化；这种情况应手动执行 SEEK ZERO。仅 PM 主控发起的运动受“先失效再运动”约束，外部控制与机械扰动不在掉电保护保证内。
